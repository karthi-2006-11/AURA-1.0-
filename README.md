# AURA — Autonomous User Request Agent
## Phase 1 + Phase 2 + Phase 3 + Phase 4: Permitted Railway Booking Workflow

A railway-focused autonomous user request agent prototype.
- **Phase 1**: Natural-Language Understanding (NLU), entity extraction, normalization, and validation.
- **Phase 2**: Autonomous AI Agent workflow, in-memory session management, contextual follow-ups, and multi-turn progression.
- **Phase 3**: Premium, modern, technical user interface, live agent workflow visualizer, and observability timeline.
- **Phase 4**: Permitted railway provider architecture, realistic mock train search, availability verification, final confirmation, and simulated ticket issuance.

---

## Safety & Compliance Architecture

> [!IMPORTANT]
> **Permitted Provider Design (Zero IRCTC Scraping / Browser Automation)**
> - AURA strictly uses an authorized provider abstraction (`RailwayProvider`) designed for permitted B2B / PSP service arrangements.
> - **Strictly Prohibited & Absent**: Web scraping, browser automation (Puppeteer, Playwright, Selenium), private API reverse-engineering, CAPTCHA bypass, credential harvesting, or Tatkal automation against `irctc.co.in`.
> - All railway schedules, availability checks, and booking results in this prototype are deterministically generated by `MockRailwayProvider` for development, demonstration, and evaluation.
> - Every mock output, ticket card, and system response explicitly displays:  
>   `"MOCK RAILWAY PROVIDER • Simulation only — no real railway ticket is booked."`
> - Generated booking references follow the format `AURA-MOCK-XXXXXX`.

## End-to-End Autonomous Workflow

```text
Natural-Language Request (e.g. "Book a train from Chennai to Coimbatore tomorrow in 3AC")
       │
       ▼
Phase 1: Deterministic NLU (Intent detection, station/date/class/passenger extraction)
       │
       ▼
Phase 2: Agent Decision Engine (Prompting user for missing parameters, context resolution)
       │
       ▼
Phase 3: Journey Review Card (User confirms journey parameters)
       │
       ▼
Phase 4: Permitted Railway Provider Search (Retrieves matching train options with schedules & fares)
       │
       ▼
Phase 4: Train Selection & Availability Check (Verifies seat quotas deterministically)
       │
       ▼
Phase 4: Final Booking Review (Clear fare summary & simulation disclosure)
       │
       ▼
Phase 4: Mock Booking Execution (Generates AURA-MOCK-XXXXXX reference & Boarding Pass)
```

## API Reference

### 1. Natural-Language Analysis (Phase 1)
- `POST /api/analyze`
  - Accepts natural-language query: `{ "query": "Book me a train..." }`
  - Returns extracted entities, normalized values, and validation status.

### 2. Conversational Agent Pipeline (Phase 2 & Phase 4)
- `POST /api/agent/message`
  - Body: `{ "task_id": "optional-id", "message": "user text" }`
  - Manages multi-turn progression, short answers, confirmation, train search, selection, and booking.
- `POST /api/agent/reset`
  - Body: `{ "task_id": "active-id" }`
  - Resets and clears the session from in-memory storage.
- `GET /api/agent/task/:id`
  - Returns current state and activity history for the specified task.
- `POST /api/agent/book`
  - Body: `{ "task_id": "active-id" }`
  - Direct endpoint to execute mock booking for an approved task with duplicate booking prevention.

### 3. Railway Provider Endpoints (Phase 4)
- `POST /api/trains/search`
  - Body: `{ "source": "Chennai", "destination": "Coimbatore", "date": "tomorrow", "class": "3A", "passengers": 2 }`
  - Returns array of matching train schedules, fares, and seat availability.
- `POST /api/trains/select`
  - Body: `{ "task_id": "active-id", "train_number": "12673" }`
  - Associates train with the booking task, validates availability, and moves status to `booking_ready`.
- `POST /api/trains/availability`
  - Body: `{ "task_id": "active-id" }` OR `{ "train_number": "12673", "class": "3A" }`
  - Returns seat quota and status (`AVAILABLE` / `WL`).
